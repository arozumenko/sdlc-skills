# Rules — qa-auditor

1. **Collect all pages before analyzing any.** Navigating resets the console/network buffers — run the full Step-0 sequence (`browser_navigate` → `browser_snapshot` → `browser_take_screenshot` → `browser_console_messages` → `browser_network_requests`) for every target page first, then run specialist passes over the complete collected set.
2. **No `browser_evaluate`.** It is not part of this factory's Playwright MCP tool set. Never instruct or attempt to call it. Data it would provide (meta tags, cookies/storage, Core Web Vitals, axe rule IDs) is unavailable — state the limitation in the finding and cap confidence at 1-4 unless the snapshot or network headers independently confirm it.
3. **Every finding cites its evidence.** Confidence 8-10 requires direct proof (screenshot region, snapshot node, network trace/header) attached to the finding. Confidence 5-7 requires at least indirect indicators. Confidence 1-4 is for educated guesses — never fabricate evidence and never report something you can't point to.
4. **Run specialists per the selection table.** Security, privacy, accessibility, content-seo, and performance always run. UX and responsive run only when their trigger signal is present in the collected evidence (forms/UI components/page-type match for UX; mobile viewport or non-responsive layout for responsive). User-scoped requests ("check accessibility") override the table — run only what was asked.
5. **Dedupe before ranking.** One finding per underlying issue across pages — merge duplicates, keep the higher priority, note all affected pages. Sort by priority descending, then confidence descending.
6. **Write the report to `reports/audit-{target}-{date}.md`.** Never a different path. Group findings by specialist, in the report template from `references/audit-methodology.md`.
7. **Only the standalone path dispatches test-author.** If the invocation prompt names a run/suite context to report back into, you were dispatched by test-run-lead's audit branch — return the report and notable findings in your final message and stop; the lead codifies. If it just names a target to audit end-to-end, you dispatch test-author yourself. Never dispatch test-author in both cases — that double-codifies the same findings.
8. **Codify only notable findings.** The Agent-tool dispatch to test-author includes only p0/p1 findings at confidence ≥5. If none qualify, skip the dispatch and say so in the summary — don't invent a codify step where none applies.
9. **Apply systematic-debugging on unexpected state.** If a page fails to load, a specialist skill can't get the data it expects, or the Playwright MCP is unavailable, capture what evidence you can (screenshot + snapshot where possible), note the gap explicitly in the report's Limitations section, and continue with the rest of the audit rather than stopping silently.
