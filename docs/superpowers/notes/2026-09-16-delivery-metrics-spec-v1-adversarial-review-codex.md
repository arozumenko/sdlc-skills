# delivery-metrics spec v1 — adversarial review (codex gpt-6-astra, round 1)

Date: 2026-09-16

## Verdict

needs-changes

Counts: **6 blockers / 16 majors / 1 minor**.

No ship. The ledger contract can discard authoritative transitions, automation capture can manufacture per-case cycle times and premature completions, and missing review evidence becomes apparent quality. Host capture, identity across plan versions, and historical aggregation also need concrete contracts before implementation. The tests currently exercise the happy paths without distinguishing these failure modes.

## Not found / explicitly fine

- Explicitly excluding DORA is correct: there is no production-deployment signal. DORA's current model has five metrics, but this spec does not claim to compute them; “four keys” in the parking lot is not treated as a shipping defect. [DORA definitions](https://dora.dev/guides/dora-metrics/).
- Cycle time from a defined start to finish, item-count throughput, WIP, and age are appropriate flow concepts; P85 is a permissible SLE probability, not a probability mandated by the Kanban Guide. The Guide itself does not mandate a universal sample-size floor. [Kanban Guide 2025](https://kanbanguides.org/the-kanban-guide/).
- Separate commit_to_done and PR-open-to-merge labels avoid falsely calling either DORA lead time or observed dispatch cycle time.
- Ordinal size classes are retained rather than silently converted to story points; calendar hours and active minutes are explicitly different units.
- No per-person/agent leaderboard is promised, and absent estimates/baselines are explicitly distinguished from zero. The quality implementation still has F5.
- Flow efficiency, benefit ROI, uploads, and manual-QA wiring are expressly out of scope; no requirement to invent them was inferred.
- The orphan placement and factory skills[] attachments have real precedents. Frontmatter keys, quoted compatibility, metadata.version, on-demand attachment, installed tests, marketplace regeneration, skills-ref, and npm validation gates are named appropriately. Package.json requires Node >=18 and uses node --test; the design should retain stdlib ESM throughout implementation.
- Copies are explicitly assigned duplicate-content checks. Deliberate independence from tokenomics imports is explained by feature-development installation; duplication alone is not a finding, but reader compatibility still needs F13.
- The shared submodule/cross-factory concern amendment is explicit, and hook opt-in, silent failure, separate installer ownership tags, and remove/doctor commands are all intended. No obsolete dual-mode/taskbox/relay architecture is introduced by the generic use of dispatch markers.
- The elapsed-time versus tokenomics active-time distinction and the existing estMin lookup defect were checked directly; neither was inferred merely from research notes.
- Review was read-only except for this note. No implementation tests were run: the proposed scripts do not exist, and the relevant failures are contradictions in their required behavior, not runtime failures of an implementation.
